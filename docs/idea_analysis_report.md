## Part 2. 사용자 커스텀 랭킹 + 구독 수익화

### 현재 랭킹 엔진 구조
```
L8 Dual Horizon Engine:
  features_short_v1.yaml → z-score 정규화 → 가중합 → score_total_short
  features_long_v1.yaml  → z-score 정규화 → 가중합 → score_total_long
  → 통합: score_total = f(short, long)
```

- 현재는 **고정된 피처 세트 + 고정 가중치**로 전 사용자 동일 랭킹
- 스코어 계산: cross-sectional z-score → equal weight 합산

### 커스텀 랭킹 구현 방안

| 방식 | 설명 | 장단점 |
|------|------|--------|
| A. 실시간 재계산 | 사용자 선택 피처로 z-score 재계산 | 정확하지만 느림 (~100ms) |
| B. 사전 계산 캐시 | 피처별 z-score 사전 저장, 선택 조합만 합산 | 빠름 (~10ms), 저장 비용 |
| C. 프론트 재계산 | z-score 전달 후 JS에서 합산 | 서버 부하 0, 보안 취약 |

**권장: 방식 B** — 피처별 z-score를 날짜×종목 매트릭스로 사전 저장, 사용자 요청 시 선택 피처만 합산

### 구독 모델 제안

| 티어 | 가격(월) | 제공 내용 |
|------|---------|----------|
| Free | ₩0 | 기본 랭킹 (5개 기본 피처), TOP10만 표시 |
| Basic | ₩9,900 | 전체 피처 선택 가능, TOP50, 7카테고리 점수 |
| Pro | ₩29,900+ | 커스텀 가중치, 알림, API 접근, 백테스트 |

### 구현 로드맵

| 단계 | 내용 | 소요 |
|------|------|------|
| Phase 1 | 피처별 z-score 매트릭스 저장 테이블 | 8h |
| Phase 2 | 커스텀 랭킹 API (피처 선택 → 합산) | 12h |
| Phase 3 | UI (피처 토글 + 실시간 랭킹 갱신) | 16h |
| Phase 4 | 구독/결제 시스템 (Stripe/Toss Payments) | 20h+ |

### 분석

| 항목 | 평가 |
|------|------|
| 기술 난이도 | **중간** — z-score 분리 저장 + API 확장 |

## Part 3. 예측 정확도 최적화

### 현재 모델 성능

| 지표 | Long | Short |
|------|------|-------|
| 앙상블 구성 | XGB 90% + Ridge 5% + RF 3% + Grid 2% | XGB 50% + Ridge 30% + RF 10% + Grid 10% |
| Holdout Sharpe | ~0.61 | — |
| XGBoost IC (train→test) | 0.733 하락 | — |

### 핵심 문제: XGBoost 과적합
- 훈련 IC 대비 테스트 IC가 0.733pt 하락 → **과적합 징후**
- Long에서 XGB 90% 가중치 → 과적합 모델에 과도한 의존

### 개선 방안

| 방안 | 예상 효과 | 난이도 | 소요 |
|------|----------|--------|------|
| 1. XGB 정규화 강화 (max_depth↓, reg_alpha↑) | +30~50bps | 낮음 | 4h |
| 2. Long 앙상블 가중치 재조정 (XGB 60%→) | +20~30bps | 낮음 | 2h |
| 3. 피처 선택 (top-k importance) | +10~30bps | 중간 | 8h |
| 4. 시간 가중 학습 (최근 데이터 가중) | +20~40bps | 중간 | 12h |
| 5. 시장 국면별 모델 분리 | +30~60bps | 높음 | 24h |

### Quick Wins (즉시 적용 가능)
1. **XGBoost 하이퍼파라미터**: `max_depth: 4→3`, `min_child_weight: 5→10`, `reg_alpha: 0→0.1`
2. **앙상블 가중치**: Long XGB `90%→65%`, Ridge `5%→20%` (안정성 확보)
3. **피처 중요도 기반 필터**: importance < 0.01인 피처 제거

### Feature Importance 분석 방향
```
현재 42컬럼 중:
- OHLCV 파생 14개: 모델 의존도 높음 (price_momentum, volatility 주력)
- 뉴스 6개: 2025+ 데이터 없음 → 모델 기여 제한적
- ESG 4개: 2025+ 데이터 없음 → 모델 기여 제한적
- 재무 5개: 연간 갱신 → 일간 변동 없음, 장기 시그널
```

### 분석

| 항목 | 평가 |
|------|------|
| 즉시 효과 | **Quick Win 1~3으로 50~100bps 개선 가능** |
| 근본적 개선 | 뉴스/ESG 데이터 갭 해소가 선행되어야 함 |
| 소요 | Quick Win 6h, 전체 최적화 40~60h |
| 리스크 | 과최적화 → walk-forward 검증 필수 |

## Part 4. 외부 지수 통합 (야간선물, 유가, VIX, 미국증시)

### 데이터 소스 확인

| 지수 | FDR 코드 | 접근성 | lag 전략 |
|------|---------|--------|---------|
| S&P 500 | `IXIC`, `SPY` | **확인됨** (FDR 작동) | T-1 (전일 종가) |
| VIX | `VIX` | **확인됨** | T-1 |
| WTI 원유 | `CL=F` | **확인됨** | T-1 |
| 야간선물(KOSPI200) | — | **미확인** (별도 소스 필요) | T-0 (당일 새벽) |
| 달러인덱스 | `DX=F` | 확인 필요 | T-1 |
| 미국 10Y 금리 | `^TNX` | 확인 필요 | T-1 |

### 통합 방식

```
1. 일별 외부 지수 수집 (FDR / Yahoo Finance)
2. T-1 lag 적용 (lookahead 방지)
3. 파생 피처 생성:
   - vix_level (절대값)
   - vix_change_1d (일변동)
   - sp500_ret_1d (전일 수익률)
   - oil_ret_1d (전일 수익률)
   - market_regime (VIX 기반 bull/bear)
4. 전 종목 동일값 브로드캐스트 (종목별 차이 없음)
5. 패널 merge → 모델 학습
```

### 핵심 고려사항
- **종목 비특이적**: 외부 지수는 모든 종목에 동일값 → 종목 간 상대 랭킹에는 직접 기여 안 함
- **시장 국면 탐지**: VIX/S&P500으로 regime 판별 → **국면별 가중치 조정**에 활용
- **야간선물**: 당일 시장 방향 예측에 가장 유용하나, 데이터 소스 확보 어려움

### 분석

| 항목 | 평가 |
|------|------|
| 구현 난이도 | **낮음~중간** — FDR 이미 사용 중, 수집 로직 유사 |
| 예상 소요 | 16~20시간 |
| 랭킹 직접 효과 | **낮음** — 종목 비특이적이므로 상대 랭킹 변화 미미 |
| 간접 효과 | **높음** — 시장 국면 탐지 → 포지션 사이즈/방향성 판단 |
| 권장 우선순위 | VIX + S&P500 먼저 → 효과 검증 후 확장 |

### 권장사항
- **랭킹 피처로 직접 투입보다 시장 국면 모듈로 활용**이 더 효과적
- 예: VIX > 25 → 숏 비중 확대, VIX < 15 → 롱 비중 확대
